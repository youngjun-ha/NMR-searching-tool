# NMRaid 아키텍처

## 데이터 흐름

1. 사용자가 ZIP, 폴더 또는 개별 파일을 선택합니다.
2. 입력 안전성 검사가 빈 관리 파일과 실제 데이터 파일을 구분합니다.
3. 형식별 파서가 스펙트럼을 공통 `{ x, y }` 포인트 배열로 정규화합니다.
4. 용매 메타데이터 또는 사용자의 용매 선택을 기준으로 용매 신호를 분리합니다.
5. 피크 탐지, 다중도 추정, 상대 적분을 계산합니다.
6. 사용자는 피크 종류·다중도·적분을 수정하거나 구간을 직접 추가할 수 있습니다.
7. m/z와 이온 모드에서 CHON 분자식, 질량 오차, DBE를 계산합니다.
8. 구조 후보가 DBE 예산을 모두 소비하는지 검산하고 관측 ppm·다중도·적분과 비교합니다.

## 설계 원칙

- 파일 내용은 외부 서버로 업로드하지 않고 브라우저 메모리에서 처리합니다.
- 0바이트 Bruker 관리 파일은 무시하지만 실제 스펙트럼 데이터가 없으면 분석을 중단합니다.
- `1r` 또는 `fid` 단독 파일도 상대축 미리보기를 제공하며, 정확한 ppm에는 메타데이터가 필요하다고 알립니다.
- 용매 영역에서는 근접한 작은 위성선을 다중도로 과대 해석하지 않고 가장 큰 신호를 `singlet` 하나로 취급합니다.
- 구조 후보는 선택 분자식의 DBE와 원자가를 먼저 만족시키고, 방향족 신호 근거가 약하면 사슬 및 사슬 내부 작용기 배치를 우선합니다.
- 자동 구조 후보는 확정 결과가 아니라 후속 2D NMR 검증을 위한 가설입니다.

## 배포 표면

- 기존 호스팅: Vinext + Cloudflare Worker (`vite.config.ts`, `worker/index.ts`)
- 독립 공개 주소: Vite 정적 빌드 + GitHub Pages (`vite.github.config.ts`, `src/main.tsx`)

두 배포 표면은 동일한 `app/page.tsx`와 `app/globals.css`를 사용하므로 분석 로직과 화면이 서로 달라지지 않습니다.
